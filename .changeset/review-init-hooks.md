Fixes for `init`, `hook` and the install guard:

- `hook install` treats a hooks folder outside the repository (a global `core.hooksPath`) as a
  conflict instead of writing into a folder shared by every repository. New option
  `allowSharedHooksPath` / `--allow-shared-hooks-path` writes there anyway.
- husky is detected from a `core.hooksPath` into any `.husky` folder, including in a monorepo
  subfolder. Hooks go into `<that .husky folder>/<hook>`, never into husky's generated `_` folder.
- The `pre-push` hook reads what git is pushing: branch deletions and tag pushes are not checked,
  and a branch is compared with the commit the remote already has. A branch that is not the
  checked-out commit is skipped instead of being judged by the wrong files.
- `hook install` no longer makes a non-executable hook executable (which reactivated a disabled
  hook): it reports a conflict. `hook uninstall` never changes file permissions.
- The Cursor guard hook falls back to `{"permission":"allow"}` when the guard cannot run, like the
  other hosts, and the guard guide says so.
- Skill, Copilot agent, Cursor rule and plugin command/agent front matter is valid YAML (the
  descriptions are quoted); a test parses every generated front matter strictly.
- `init` only refreshes skill, agent and rule files that carry the
  `<!-- generated by autoremediator init: safe to regenerate -->` marker. A file without it is
  reported as a conflict and left alone; delete it and run `init` again to have it managed.
- Merge helpers no longer throw on unusual `.claude/settings.json` shapes (conflict instead), refuse
  a Codex `config.toml` that defines the server with dotted keys or an inline `mcp_servers` table,
  recognise the rooted `/.autoremediator/` ignore entry and move negations that come before the
  `.autoremediator/*` line, and keep CRLF line endings in `AGENTS.md`.
