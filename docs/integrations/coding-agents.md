# Coding agents

Claude Code, Cursor, VS Code with Copilot, Codex and Gemini CLI can all drive Autoremediator through
its [MCP server](mcp-server.md). One command sets a project up for the ones you use:

```bash
npx autoremediator init
```

It looks at the project, shows what it would write as a diff, and writes it when you confirm (or
pass `--yes`). The agent proposes changes and the [verifier](../guides/plan-and-apply.md#verify)
decides whether they are kept, so an agent can be given these tools without trusting it.

## What `init` does

| It finds | It uses it to |
| -------- | ------------- |
| Package manager, git host, CI | Report what it sees; write the workflow with `--ci` (GitHub Actions only) |
| Agent hosts: a config folder or instruction file in the project, otherwise a host's command on `PATH` | Choose which hosts to configure. Override with `--hosts claude-code,cursor` |
| Model API key variable **names** that are set | Report them. Values are never read into the output |

| File | For | Written |
| ---- | --- | ------- |
| `.github/autoremediator.yml` | everyone | Only when missing. Conservative defaults: no major bumps, 72 hour cooldown, no install scripts, KEV is mandatory |
| `.gitignore` | everyone | Adds `.autoremediator/` |
| `AGENTS.md` | any agent | A marked section: how to plan, apply, repair and roll back, and the exit codes. Text outside the markers is never touched |
| `.mcp.json`, `.claude/skills/*/SKILL.md` | Claude Code | MCP server and three skills (`fix-cve`, `repair-upgrade`, `vet-dependency`). With `--guard`, also a `.claude/settings.json` hook that [checks package installs](../guides/guard.md) |
| `.cursor/mcp.json`, `.cursor/rules/autoremediator.mdc` | Cursor | MCP server and a rule |
| `.vscode/mcp.json` | VS Code | MCP server (`servers` key, `"type": "stdio"`) |
| `.github/agents/autoremediator.agent.md` | Copilot | A custom agent |
| `.codex/config.toml` | Codex | An `[mcp_servers.autoremediator]` table |
| `.gemini/settings.json` | Gemini CLI | MCP server |
| `.github/workflows/autoremediator.yml` | GitHub Actions | With `--ci`: weekly run that opens a pull request |

Rules it follows:

- **It merges, never replaces.** Other MCP servers and your own settings stay. An existing
  `autoremediator` entry is left exactly as it is, so changes you made (an `env` block, a different
  command) survive.
- **It refuses what it cannot merge.** A config that is not valid JSON, or has the wrong shape, is
  reported as a `conflict` and left alone. So is a Codex `config.toml` that defines the server with
  dotted keys or an inline `mcp_servers` table, which cannot be extended without a duplicate.
- **It only refreshes files it generated.** The skills, the Copilot agent and the Cursor rule carry the
  line `<!-- generated by autoremediator init: safe to regenerate -->`. A file at the same path
  without that line is yours (or was written by an older release, which wrote no marker): it is
  reported as a `conflict` and left alone. Delete the file and run `init` again to have it managed.
- **Nothing is written without a yes.** In a terminal it asks. Without a terminal (or with
  `--output-format json`) it prints the diff and exits `3` ("waiting for approval") unless you pass
  `--yes`.
- **`--check`** writes nothing and exits `1` when any file is missing or out of date, so CI can keep a
  project's agent setup from drifting.

The MCP entry runs `npx -y -p autoremediator@^<version> autoremediator-mcp`, pinned to the version
range of the CLI that wrote it. Re-run `init` after upgrading to move it.

## Claude Code plugin

Instead of per-project files, install the plugin once:

```text
/plugin marketplace add Diffra/autoremediator
/plugin install autoremediator@autoremediator
```

It adds the MCP server, the [install guard hook](../guides/guard.md), the three skills, two commands (`/autoremediator:remediate <id>`,
`/autoremediator:vet <package>`) and a `dependency-remediator` subagent. The plugin lives in
[`integrations/claude-code`](../../integrations/claude-code) and is generated from the same text `init` writes,
so the two cannot disagree.

## Per host notes

- **Cursor.** Rules are written to `.cursor/rules`. A Cursor plugin package is not provided yet.
- **VS Code and Copilot.** VS Code reads `.vscode/mcp.json` directly. The Copilot custom agent file
  works in VS Code; the Copilot cloud agent takes its MCP servers from the repository's settings on
  GitHub, which `init` cannot write.
- **Codex.** Project `.codex/config.toml` is only read for projects you have marked trusted.
  `AGENTS.md` is read either way.
- **Gemini CLI.** Written to `.gemini/settings.json`.
- **Any other MCP host.** Use the entry from the [MCP server](mcp-server.md) page.

The file formats come from each host's public documentation as of this release. The Claude Code
plugin has not been checked with `claude plugin validate`; report a host that rejects what `init`
writes.

## What an agent does with it

1. `planRemediation` for an advisory: nothing changes, a run id comes back.
2. Show the plan to the person, then `applyPlan`. Each item is verified and taken out again if it fails.
3. If an upgrade breaks the project, `startAttempt` opens an isolated checkout; the agent edits
   project source there (or sends a diff with `proposePatch`), `verifyAttempt` judges it, and
   `finalizeAttempt` keeps it. The agent cannot touch `package.json`, lockfiles, CI or the policy.
4. `rollbackRun` undoes a run.

See [Plan, apply and roll back](../guides/plan-and-apply.md) for the full flow and
[Automation and CI](../guides/automation.md#exit-codes) for the exit codes an agent can branch on.
